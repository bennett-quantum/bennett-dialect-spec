# Dialect 0.3 S0 review — sol

**Verdict: revise. Two S0 findings.** Both concern the new qreg table's object representation. They are independent: repairing its image leaves the range collision; moving it leaves the invalid image. Beads are open for implementation; this review changes no contract.

Reviewed [draft 0.3](../../spec/Bennett-Dialect-Spec-0.3-draft.md) and its [acceptance dossier](../notes/2026-11-01-dialect-0.3-dossier.md) against [ISA 0.9](../../../bennett-isa-spec/spec/Bennett-ISA-Spec-0.9.md) and the [NorthStar](../../../bennett/docs/Bennett-NorthStar.md). Clause/line citations below refer to the source hashes at the end. S0 means an unimplementable or unsound contract, or a narrowing of a NorthStar capability. Compilation cost alone and missing consumer implementation are not findings here.

| Finding | Defect | Bead |
|---|---|---|
| SOL03-S0-01 | The prescribed qreg-table range overlaps coherent memory | `b-dialect-spec-d4s` |
| SOL03-S0-02 | An empty image cannot encode the prescribed positive-size table data symbol | `b-dialect-spec-fa8` |

## SOL03-S0-01 — The qreg table occupies addresses already assigned to coherent memory

**Clauses.** Draft §6.5, line 1773, introduces `__bennett_rt_qtab` as a classical global above the heap. §19.5, line 11229, fixes its base to the first 4096-byte multiple at or after `heap_base + heap_limit_max`, preserving every other global and heap address. But §16.3, lines 8110–8114, places the first interface region at its aligned heap end when no arena exists. TDL-4 and §19.5 independently place the arena above the same heap end. ISA §§7.1–7.2, lines 1577–1605, require disjoint global, heap and interface ranges; TDL-4 also requires the arena to be disjoint from CC globals.

**Concrete witness.** The full marker source is `SOURCE` in [the executable witness](2026-11-02-sol-0.3-s0-witness.py). A host invokes `stash`, then `read_db`, closing each completed launch before the next:

1. `stash` allocates one clean wire and stores its handle in the internal global `@held`, retaining it across the device-entry return. The entry-boundary test of §6.5 therefore requires the qreg table; the optional static file cannot discharge that lifetime.
2. `read_db` allocates a clean eight-wire database, an eight-wire target and a four-wire fault register. Its descriptor binds `query(ptr db) { return *db; }` with `MEM_IN(size=1)`. Two identical oracle calls restore the targets; all registers, including `@held`, are freed clean.

Use `--bennett-budget-default=64,0,32,8,0` and `--bennett-qreg-table-bytes=4096`. The source globals occupy less than one page starting at 4096, so `heap_base=8192`; `heap_limit_max=0`. No source object is made Co, so there is no arena. The oracle has one interface byte:

```text
heap:        [8192, 8192)       (empty)
qreg table:  [8192, 12288)      (§19.5)
m0:          [8192, 8193)       (§16.3, region[0,8])
```

Thus even a one-byte quantum-addressed input collides. With the default table size the overlapping range is larger. This is not heap exhaustion or an invalid binding. The arena has the same problem: for example, a page-aligned heap end at 8192, a 4096-byte arena and a 4096-byte table assign both `[8192,12288)`.

Restricting a standalone reference object's globals to its L closure (§16.3) does not remove the table from the device link layout: §19.5, lines 11211–11220, requires every link global and its oracle interface regions there. ISA §9.3, lines 2060–2067, requires validation when linking. A producer cannot repair the complete device layout merely by omitting the table from an isolated oracle example.

**Independent check.** The witness builds a small ISA 0.9 admission fixture with these ranges, using a complete zero image to isolate this finding from SOL03-S0-02. The reference interpreter rejects it with:

```text
§7.2: overlapping layout ranges m0 and qtab
```

Moving only the table to `[12288,16384)`, keeping `m0` and the heap fixed and recomputing hashes, produces an admitted control object. This checks the layout conflict, not execution of a compiler-generated qreg table.

**Why S0.** The draft requires this combination to be accepted (§1.2, §25.1), yet its prescribed layout cannot be loaded. Handle collections and registers surviving calls are promised by NS §3.1 and §5; quantum-addressed memory is central to NS §4.2 and §8 rung 4. Forbidding their combination would narrow those promises. The one-byte witness establishes the defect without asserting that the existing reduced SQLite example itself allocates a qreg table.

**Required change.** Reserve disjoint storage for plugin-private table state after accounting for globals, heap, arena and interface ranges, while retaining observable program addresses and reference budgets. Check table-plus-`MEM_IN` and table-plus-arena objects together. A layout rejection or an additional runtime fault for this valid combination is not a fix.

## SOL03-S0-02 — E4 does not provide a zero-fill encoding for a nonempty table

**Clauses.** Draft §19.5, line 11229, requires the qreg table in `layout.globals` “with an empty data image (ISA E4)”. §6.5, line 1773, requires records and a counter; §24 D29, line 11742, sets a positive storage capacity. ISA §9.1, lines 1916–1929, defines the global and data-symbol schemas and `NAME SP HEX` data lines. ISA §9.2, lines 1991–1994, requires every global's image to name a data symbol of that size. E4 (§0.1, line 85; §16.1, lines 4073–4075) permits the trailing space in an empty data line. It supplies no sparse image or BSS size/zero-fill contract.

**Concrete witness.** Isolate the encoding from the collision by putting the table at the disjoint control address:

```text
layout global: qtab { base:12288, size:4096, image:qtab }
data signature: { abi:"0.9", kind:"data", size:4096, tier:"-" }
data line: "qtab " followed by LF (zero encoded bytes)
```

The reference interpreter rejects this object with:

```text
§7.2: data size differs from signature
```

Keeping the address, declared size and oracle fixed, replacing empty HEX with 4096 zero bytes (8192 hex digits), and computing the symbol hashes with the interpreter admits the control object. Declaring the data symbol size zero instead would contradict the required same-size global and provide no record storage.

**Why S0.** Every required table site needs a positive-size table, so the specified representation fails before any register instruction executes. NS §3.1 handle collections and §5 persistent register lifetime cannot be implemented by this encoding. The dossier's decisions 2–4 adopt this table and its §25.1 BLK-1 retirement, but the blocked `k1-table` row supplies no execution evidence for the empty-image construction.

**Required change.** Emit a complete declared-size zero image under the existing ISA, or obtain an explicit published ISA zero-fill representation before using one. E4 alone is insufficient. Add an admission witness that checks a positive-size table's data symbol, image, initial state and hashes. This fix is needed even when the table's placement is disjoint.

## Reproduction and limits

Run from the repository root:

```sh
env -u DISPLAY -u WAYLAND_DISPLAY -u DBUS_SESSION_BUS_ADDRESS -u BROWSER \
  TMPDIR="$PWD/.tmp/sol-dialect-s0/tmp" \
  python3 -B docs/reviews/2026-11-02-sol-0.3-s0-witness.py
```

Observed result: **exit 0**, meaning all counterexample assertions and the admitted control passed:

|---|---|

| Marker source: `opt-23 -passes=verify -disable-output` | exit 0 |
| Disjoint table, empty image | rejected: `data size differs from signature` |
| Overlapping table, full zero image | rejected: `overlapping layout ranges m0 and qtab` |
| Disjoint table, full zero image, interpreter-computed hashes | admitted, `status:ok` |

Executor: `.tmp/dialect03/isa-ref/4900508957bfd4aa/reference-interpreter/target/release/bennett-isa-ref`; SHA-256 `20bcba9f352edcca56f651ec2e6b25e08b9f22ca688b6684855211b3a8ec7012`. `--ref /absolute/path/to/bennett-isa-ref` selects another built interpreter. Each subprocess has a 30-second timeout; temporary files are created and removed under `docs/reviews`.

The two negative objects intentionally fail structural admission before symbol-hash validation. The positive control is hashed by the interpreter and passes full `check`. The ISA fixture is a minimal layout counterexample, not the canonical §16 reference map of the marker source. LLVM verification establishes source IR validity; it is not a dialect recogniser or plugin execution claim.

The dossier honestly labels its six K1–K4 rows unexecuted. Those implementation gaps alone are not additional S0 findings. Neither are full-domain shape-dispatch cost, conservative coherent-width padding, or the pointer-fixpoint performance issue already tracked as `b-dialect-spec-5u3`. A budget depending on superposed data is outside NS §4.2's classical-budget promise; its existing `b-dialect-spec-0nn` question is not promoted to an S0 here. The constrained-FP exception and aggregate-varargs candidates did not establish an unavoidable contract contradiction and are excluded.

The repository freeze gate was not run: `scripts/pre-push` invokes git and creates a sibling worktree, contrary to this job's runner/owned-path rules. The 0.3 pre-flight also invokes git to build its interpreter. This review makes no new all-green claim for either draft. Its evidence is the bounded source-verification and object-admission command above.
