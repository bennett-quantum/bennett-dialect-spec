# Dialect draft 0.3: dossier for the acceptance round

Draft: [`spec/Bennett-Dialect-Spec-0.3-draft.md`](../../spec/Bennett-Dialect-Spec-0.3-draft.md). Grading target: ISA 0.9. 0.2.12 is byte-unchanged and its gate still applies to it.
Pre-flight: `tools/dialect_check_v03.py` (see `tools/README.md`). Receipt: see the last section.

## Decisions taken without a ruling (for the council to check)

1. **Version string `0.3`**, file named `-draft`. Sub-versions: handles, regions, oracle-abi, tdl, effects, map, platform and driver move to 0.3; norm stays 0.2.8; markers, asm and corpus stay 0.2.
2. **Tags are not ids.** ISA ids are executor-chosen `i64` values that may be 0 or exceed 2^pw, so pointer-width tags stay and a table maps them (§6.1, §6.5). Tags are never reused.
3. **Table placement.** `__bennett_rt_qtab` is a zero-image global above the heap, so it moves no program address (§19.5). Exhaustion is code 2, like the heap. The default size (D29) is my choice.
4. **Interning.** A register entering through `QREG` gets its existing live tag, so tag equality stays identity (§6.3).
5. **Hoisting removed.** R uses `qreg.*` directly (§7.5(b)). The bounded static file stays optional in CC; nothing depends on it.
6. **`hostcall bennett.fault` removed.** CC uses `fault C` too, because K5 needs no host service (§11.5).
7. **A terminal R fault skips exit handlers and flush** (§19.2). This follows from K5; it is new text for lbq.
8. **Lowering report** replaces the blocker report and carries no verdict. Status 3 stays defined for a future blocker but is never used on 0.9.

## Weak points to attack

- **§8.4 and D34: full-domain shape dispatch.** The ruled construction names up to 2^64 reference objects, so no plugin can emit it in full. D34 lets a plugin report unfinished emission at build time and forbids a run-time `T-IFACE` for a valid shape. In practice a program with a truly unbounded oracle width will fail at build time, which is close to a narrowing even though it is honest. The real fix is an ISA request, `b-isa-spec-lpe` (width-parametric regions), filed with exact text. This is the one place where I doubt the ISA 0.9 text is enough; it is classed as efficiency because the ruling says so.
- **TDL-10 full-domain pad**: a top Co width asks for 2^64−1 wires, so on any real device it is code 2 at allocation. It is a defined outcome and the ruling's construction, but it is not a useful execution.
- **The qreg table is unexecuted.** `k1-table` will be the first run of §6.5's design.
- **Cross-run persistence.** §6.5 assumes device memory persists across runs of one loaded program. ISA §10's ownership text implies that but does not state it in so many words, and 0.2's cross-entry examples assume the same. `k1-table` runs in one entry only.
- **Co budget fields**: §9.5 mints classical tuples only. A budget field that is Co inside a generation has no explicit rule in 0.2.12 or here, and K3 cannot mint from a location.
- R1 evidence: [`2026-11-01-r1-coherent-lifting.md`](2026-11-01-r1-coherent-lifting.md).
