# Dialect draft 0.1: audit for narrowings of north-star scope

**Date:** 2026-10-29. **Phase 0** of `bennett/docs/plan/2026-10-29-path-to-north-star.md`.
**Audited:** `spec/Bennett-Dialect-Spec.md` draft 0.1 (commit 255b0f4), all sections.
**Yardstick:** `bennett/docs/Bennett-NorthStar.md` iteration 7 (§0, §3, §4, §5, §8).
**ISA consulted:** `bennett-isa-spec/spec/Bennett-ISA-Spec.md` draft 0.8.
**Decided, not audited as narrowings:** the three maintainer decisions of
`docs/spikes/2026-10-28-legality-findings.md` §3 (region identity by content; handle
provenance through bitwise copies; region operands dispatched at run time).

**Standing rule applied.** No narrowing of north-star scope of any kind. A deferral
may postpone *mechanics* while keeping the capability. A default of reject, refuse,
none, fault or no effect for something the north star promises is a narrowing.

**Classes.** **N**: narrowing. The rule excludes something the north star promises.
**M**: mechanics-only deferral, or not restrictive at all; the capability is kept.
**L**: legitimate. The north star itself requires the rejection, or a maintainer
decision settles it.

Citations: "NS §n" is the north star, "ISA §n" is ISA 0.8, and a bare "§n" is
dialect 0.1. "Rungs" means the demo ladder of NS §8:

1. scalar functions
2. pointers, structs, byte memory
3. musl hello world
4. Grover over SQLite
5. Julia on a shim runtime
6. xv6 and Linux in the reversible tier
7. kernel fuzzing
8. Monte Carlo amplitude estimation

## 0. Summary

**Counts.** 96 rows are classified (§1 table): **N 57, M 12, L 27**.

- 17 of the N rows only point at another row with the same mechanism:
  - the 13 `see …` body rules;
  - B-17's N half (→ D11) and O-05 (→ 1.4-d);
  - D17 (→ 1.4-d) and D18 (→ 1.4-e).
- That leaves **40 distinct narrowings**, 7 of them omissions: capabilities the north
  star promises but no rule of the draft covers (§1.D, O-01..O-07).
- B-17 and B-38 are mixed rows. Each is counted as N above, and its L part is noted
  in the row.

The plan's list of known narrowings (D2, D6, D10, D11, D16, D17, D19, D21, D23, plus
D4) is confirmed with two adjustments:

- **D23 (full LTO only) is M.** Every program can be merged into one module. The
  narrowing is the companion rule §11.1 "MUST do nothing in any … per-translation-unit
  phase", which removes the per-TU fast path that NS §3.3 promises (row B-54).
- **D1, D3, D8, D9 and D14 are also N.** So are the §4.2, §5.2–§5.4, §6.2 rule C3 and
  §6.5 body rules, and 8 omissions.

**Not gaps:**

- ISA-2: an R budget can be enforced by instrumentation; only its fault code needs ISA-7.
- ISA-6: `measure` followed by re-preparation is exact.
- ISA-10: the normative test vectors of ISA §16.3 settle it.
- The oracle half of ISA-3: oracle `args` exist (ISA §4.7, §5.1, §9.1); only the JCS
  spelling of argument types is editorial.

**R1 (§3 of this audit).** ISA 0.8 permits taint-inferred lifting of classical code
inside `ctrl` bodies into lifted oracles that the action calls. No ISA change is
needed for the capability. G-13, G-14 and G-15 are efficiency items. The draft's
stated reason for the §1.4 departure ("the ISA 0.8 action body has no classical
computation") is true but does not imply the conclusion: actions call oracles, and
oracles compute (ISA §5.3, §4.7).

**Top ten narrowings by impact** (mechanisms in §1):

1. **D4** (oracles are scalar only). Lift the full LLVM subset onto ISA `lift.*`
   memory, call and alloc rows, with soft-float as lifted lprocs.
2. **D21/D3/B-32** (oracle signature `iT (iN)`). Add an oracle marker whose interface
   binds several input registers, `mem` interface regions and classical `args`
   (ISA §4.7, §5.1, §7.2).
3. **D11** (no effects). Add effect markers or recognised runtime primitives lowered
   to ISA `effect` (ISA §7.3), and lifted-memory device models in the coherent tier.
4. **O-01** (indirect calls unspecified). Use candidate sets, function-address
   encoding, and compare-chain dispatch to static `call` / `lift.call`.
5. **1.4-d / D17** (no coherent lifting under `ctrl`). Taint-driven lifting as in §3:
   coherence lattice, outlined slices as oracles, a coherent arena, history registers.
6. **B-42 / D2** (budget is steps only, (B,0,0,0)). Add a four-component budget
   (steps, heap, stack, depth) from out-of-band tables keyed by region identity.
7. **O-04** (no whole-program tier mode). Add a driver mode that runs an unmodified
   program's entry in the R tier (whole-run reversal, ISA §10).
8. **O-02 / O-03** (inline asm, varargs). Add an asm classification table
   (lowered / shimmed / trapped) and a lowering of `va_*` onto memory.
9. **B-24 / B-26 / B-27 / D9** (handles in collections). Replace the base analysis
   with a field-sensitive whole-program points-to analysis covering every allocator
   and call result, plus run-time `T-DEAD` for the residue.
10. **B-16** (`BD-E-DEVICE-ADDRESS`). Polyvariant cloning of device functions
    (NS §3.1): host and device copies, with address mapping through the comparison
    link map.

## 3. The §1.4 departures; taint-driven lifting under `ctrl` (R1)

### 3.1 The departures other than the three decisions

- **1.4-d / D17 (coherent code only through `oracle`/`inplace`; generation for
  `ctrl`/`adj`/`compute`).** N. The draft's reason is "The ISA 0.8 action body has
  no classical computation (ISA §5.3), so a body whose circuit depends on classical
  data can only be expressed by classical generation".
  - The premise is true: ISA §5.3 lists no classical rows.
  - The conclusion only covers classical data that determines the *structure* of the
    circuit (indices, op codes, trip counts of gate loops). Generation remains right
    for that.
  - It does not cover classical data that is itself *under control*: memory written
    by the body, and values derived from such memory. ISA 0.8 expresses those as
    lifted oracles the action calls, as §3.2 below shows.
  - The draft's semantics also change results rather than only rejecting programs:
    under `ctrl(q, f)` a classical store of `f` to memory that outlives the region
    happens on both branches of q.
- **1.4-e (budgets inert).** N; it follows from 1.4-d. With §3.2, the `ctrl`
  budget becomes the token of every outlined slice.
- **1.4-f (`inplace` without classical arguments).** N, with a genuine ISA gap
  (ISA-3).
- **1.4-g (no clean-target rule for `qstore`).** Not a narrowing.
- **1.4-h (normalise the whole device closure).** Not a narrowing.

### 3.2 Does ISA 0.8 permit taint-inferred outlining inside `ctrl` bodies? Yes.

The ISA operations involved:

- ISA §5.3: an action body contains `oracle_call`, `qexch`, `qexchm`, `qstore`,
  `qpred`/`qif`, `qalloc`/`qfree`, and gates.
- ISA §4.7: "`oracle_call @o tk (ins..) tgt fr (mem..) (args..)` … `ctl w <call>` ≡
  the call under `qpred w`. In CC and R, wire and region slots are filled by `qreg`
  operands". Region calls, controlled ones included, can therefore be issued
  directly by device CC code.
- ISA §5.2: an oracle is an involution and its own adjoint.
- ISA §5.5: a nested oracle's fault register is cleaned by its matched uncall or
  retained.
- ISA §3.1: "Gate angles are finite `f64` literals or classical arguments fixed at
  region entry", so classical values enter an action as `args`.
- An oracle can materialise a classical argument into wires (`tgt ^= a`).

The draft's generation model (§8.4: classical code runs in CC and issues events)
stays. It is extended with oracle events for the coherent part.

**Taint-driven lifting (TDL), specifiable as dialect 0.2 rules:**

- **TDL-1 Interface vs body.** The marker fixes the region's *interface* (action for
  `ctrl`/`adj`/`compute`, oracle for `oracle`/`inplace`). The body is partitioned by
  content (TDL-3), never rejected for containing classical code (NS §4.2).
- **TDL-2 Coherence lattice.** Values are Cl ⊑ Co. Each abstract object (the
  field-sensitive objects of B-24) has a flow-sensitive state Cl or Co.
  - **Seeds:**
    - (a) a store executed during the generation of an action region to an object
      that is live after the invocation (reachable from `env`, a global, or a heap
      object not freed in the region) makes the object Co from the region's exit.
      This is promotion: under control the object's contents are superposed.
    - (b) a load from a Co object is Co.
  - **Propagation:**
    - data dependence;
    - control dependence: a Co branch makes the instructions dependent on it Co, and
      their stores predicated;
    - memory: a store of a Co value, or a store under Co control, makes its object
      Co.
  - The analysis is interprocedural and context-sensitive, with polyvariant clones
    per coherence signature (NS §3.1).
- **TDL-3 Partition.**
  - **G (generation)** is the set of Cl instructions that are not control-dependent
    on a Co branch and whose stores target Cl objects or non-escaping objects. G runs
    once in CC, as today.
  - **Coherent slices.** Each maximal single-entry single-exit region of Co
    instructions is outlined (CodeExtractor) into O_k. Its interface is:
    - Cl live-ins become classical `args`;
    - Co live-in values become input registers;
    - the Co objects it reads become the arena region (`in`);
    - Co live-outs and the new contents of the bytes it writes become output targets.
  - O_k is lifted by the D4 map. Irreducible coherent code is outlined as a whole
    function.
- **TDL-4 Coherent arena.** Every object that may become Co is allocated in the
  coherent arena.
  - The arena is a static address range [A_coh, A_coh + 2^A) in the layout, inside
    every oracle's [0, 2^H) and disjoint from the CC globals and heap. ISA §7.1/§7.2
    force this: interface regions cannot overlap CC memory (G-13 would remove the
    restriction).
  - Its contents live in a CC-held `qreg[8·2^A]` bound to `region[A,8]` (ISA §3.3
    binding).
  - The `bennett-runtimes` coherent allocator keeps its bookkeeping classically. A
    still-Cl arena object has a CC shadow at a fixed offset; G-code stores to it are
    mirrored as basis-state updates (X on changed bits through `action_call` on
    slices).
  - After promotion, CC code that reads the object is a compile-time error
    (`BD-E-TAINT-HOST`): host-visible outputs leave only through measurement
    (NS §4.2, effects table, coherent row).
- **TDL-5 Events.** `gen(R, env)` appends events in two cases.
  - **Case A.** A G store to an escaping object whose old and new contents are both
    classical appends `xmask o, old⊕new`: X on the changed bits of the arena cells.
    No oracle is needed.
  - **Case B.** At each dynamic entry into slice O_k it appends `oracle O_k` with:
    - `args` = the current Cl live-ins;
    - `ins` = the registers of the Co live-ins;
    - `mem` = the arena;
    - `tgt` = fresh registers for the Co live-outs and the new contents of the
      written bytes;
    - `fr` = a fresh `wire[4]`.

    It then appends exchange events that move the new contents into the arena:
    `qexch` on slices for classical addresses, `qexchm name a v` for Co addresses
    (ISA §4.6). The displaced old contents stay in the `tgt` registers.
  - Oracle outputs wider than 128 bits are sliced (G-15).
- **TDL-6 Control and adjoint.**
  - `ctrl` adds the control wire to every event's control set (draft §8.3), i.e.
    `ctl w` on each call (ISA §4.7).
  - The adjoint list exists because `oracle_call`, `qexch`, `qexchm` and X are
    self-adjoint (ISA §5.3 adjoint table).
  - An `adj` of a region with escaping writes consumes the history registers its
    forward invocation produced. Without them the adjoint of a non-injective update
    does not exist. That case is L: NS §4.2 requires an action to be a unitary on its
    declared wires.
- **TDL-7 History.**
  - What history holds: displaced contents, per-slice fault wires, and Co
    temporaries that are no longer needed.
  - Where it lives: declared mutable wires of the invocation.
  - When it is freed: the scheduler chooses (NS §3.1 garbage row). `compute(f, use)`
    frees it through adjoint(E_f).
  - This is how the NS rule "every other write being restored workspace" (NS §4.2)
    is met for writes to memory that outlives the region: the memory is versioned,
    never overwritten.
- **TDL-8 Faults.** A final combine oracle XORs the first nonzero per-slice code into
  the region's declared fault register. Its `ins` are the per-slice fault wires; its
  body is a lifted `select` chain.
- **TDL-9 Budget.** The `ctrl` operand, or the D2 table, gives (steps, heap, stack,
  depth) for every O_k token. Exhaustion is that slice's `FAULT_BUDGET_*`, which
  reaches the region fault (NS §3.1 budget row).
- **TDL-10 Co control of quantum operations.**
  - A marker call that is control-dependent on a Co branch, or that has a Co index or
    op code: an oracle computes the condition into a fresh wire, and the gate is
    issued under `qpred` once per candidate (index in [0, n(h)), op table) (ISA §3.5,
    §4.6).
  - A Co angle is predicated per candidate when its candidate set is finite, and is
    otherwise rejected. That rejection is L: the NS promises predication, not
    superposed parameters.
  - A Co trip count of a loop that issues gates is padded to the budget bound,
    unrolled in the event list, with per-iteration flags kept as history.
  - G-14 would replace that history with an action step machine.

**Consequence.** No ISA change is needed for the capability. G-13 (dynamic region
base), G-14 (action step machine) and G-15 (wide oracle payloads) are efficiency
items for ISA 0.9. ISA-4 matters for `adj` of a generation whose register set is
known only at run time: the event trace must be recorded with its registers and
replayed in reverse. With a static register set the trace stores indices and needs no
`qreg` in memory.

R1 is therefore a dialect design task for phase 3, with no ISA blocker. Rungs 4, 7 and
8 do not depend on it, because their oracles are entered through the explicit
`oracle` marker once D4, D21/D3, D11, B-42 and O-01 are removed.
