## What the dialect spec must say because of this

1. Julia must use `Base.llvmcall` with the `(module_ir_string, "entry")` form containing a `declare` for each marker. Any `ccall`/`@ccall` (with or without library) produces an opaque indirect call through a lazily-bound GOT global, so no `call @__bennett_*` and no `declare` exist. The legacy `(declarations, body)` two-string and the body-only forms do not work on 1.13 (`ir/rD0_alloc.unopt.ll`, `ir/rD1_alloc.unopt.ll`). If ccall must be supported, the extractor would have to key on the `"julia.fname"` attribute of the `jlplt_*_got` global, which is a Julia-internal convention and has absolute addresses baked in for loadable libraries.
2. The spec must not require `i1` returns for `bool`: it must say "a `bool` marker result is `zeroext i1` (C, C++, Rust, llvmcall-as-written) or `i8` (Julia ccall); consumers must accept both", or the Julia front end must route through llvmcall.
3. Unwinding. Clang and rustc `extern "C"` are not uniform: C and Rust `extern "C"` add `nounwind` (Rust on the declaration and every call site; C only as a call-site addition at -O2), C++ `-fexceptions` and Rust `extern "C-unwind"` emit markers as `invoke`. The spec must either require "markers never unwind" and tell front ends how to declare them (`noexcept` / `__attribute__((nothrow))` / `extern "C"` in Rust) so `invoke` does not appear, or require the extractor and every consumer pass to handle `invoke`+`landingpad`. `nounwind` is an L2 observation, not a violation, but must not be treated as "marker is pure".
4. Region identity: the function pointer given to a region marker is not always the user's function. C++ lambdas pass the `__invoke` thunk (`@"_ZZ10case_entryEN3$_08__invokeEPv"` which calls `operator()`); Rust closures pass a generic `extern "C" fn tramp<F>` instance; Julia `@cfunction` yields either an integer constant (no symbol) or a `jlcapi_*` wrapper that forwards through `jl_get_abi_converter`, and the markers inside the Julia region body are in a different module (`declare swiftcc void @j_body_914`). L4 must be defined on "the symbol that is passed, and what it contains", and the dialect must say how a front end hands over a region as a defined symbol; for Julia a region must be an llvmcall-embedded function in the same module, not a `@cfunction`.
5. Region pointers can be runtime values at O0 (C++ lambda conversion operator call, Rust `region_of()` call); only after optimisation do they become constants. The extractor, if run before optimisation, must either follow those calls or reject non-constant regions.
6. Env pointer: C/C++/Rust pass `alloca`s (`ptr noundef %6`, `ptr %e`); Julia passes a heap `Ref` (`pointer_from_objref`) under `gc_preserve`. Any pass that sinks stores into the env past the marker would break it; the spec's no-memory-attribute rule is what prevents that (confirmed: none of the front ends adds one).
7. Front ends add parameter attributes the spec must tolerate on declarations: C `noundef`; Rust O2 `noundef` on returns and `nonnull` on `bregion` params; clang `nonnull` on fn-pointer/env args at call sites, `tail`; `local_unnamed_addr`/`unnamed_addr` everywhere. The "no attributes beyond what the front end adds by default" wording is right, but the L2 diff should list `nounwind`, `nonnull`, `noundef`, `unnamed_addr`, `local_unnamed_addr`, `tail` as expected-benign. A driver-side strip is NOT needed for the eliminating attributes: none of C, C++, Rust or Julia adds any.
8. The variadic marker is emittable in all four (C/C++/Rust: `declare ..., ...` with explicit function type at call sites; Julia: llvmcall, or ccall `Cint...`/`@ccall ...;`). Promotion rules apply (`i32` int, `double`), and in Julia ccall it is a dlsym phi callee.
9. Rust: mixed `extern "C"` and `extern "C-unwind"` declarations of one symbol give a `clashing_extern_declarations` warning and one `declare` (`nounwind`) with `invoke` call sites; the spec should require one ABI per marker per crate.
10. Toolchain notes: `rustc` needs `--edition 2021` for `core::`; Julia's `code_llvm(...; raw=true, dump_module=true)` output parses and verifies with LLVM 20's `opt`; the Julia IR contains Julia address spaces (10/11) and absolute JIT addresses and so is not a stable artefact for the legality harness; use route D with `.ll` text.

## Orchestrator correction (2026-10-28, verified)

A third Julia route, missed above and found by the Enzyme prior-art survey (`../docs/spikes/enzyme-prior-art.md`):
`ccall("extern __bennett_qalloc", llvmcall, Ptr{Cvoid}, (UInt64, UInt64), 0, n)` emits a **direct call to an
attribute-free declaration**, Julia 1.13.3, `code_llvm(...; raw=true, dump_module=true, optimize=true)`:

```
%2 = call ptr @__bennett_qalloc(i64 0, i64 %"n::UInt64"), !dbg !22
%3 = call ptr @__bennett_qalloc(i64 0, i64 %"n::UInt64"), !dbg !22
declare ptr @__bennett_qalloc(i64, i64) local_unnamed_addr
```

Both calls of a function that calls it twice survive Julia's optimiser. This is lighter than the
`Base.llvmcall((module_ir, "entry"), ...)` form and is the candidate emission route for Bennett.jl.
